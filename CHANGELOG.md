# Changelog

All notable changes to `ranetrace-php` will be documented in this file.

This file starts here, so releases before it are not recorded; the git history is the record for those.

## [Unreleased]

### Added
- **This package is now the one home of the four wire payload shapes, the endpoint table and the response matrix.** `ranetrace/ranetrace-laravel` builds its error, log, event and JavaScript-error items here instead of keeping a second description of the same field sets, addresses its batches from the same table, and reads the same per-status decisions. Two descriptions of a strictly-matched field set eventually disagree, and the disagreement surfaces as a backend 422 that discards a whole batch rather than as a failing test in either repo
- `Http\Endpoint` and `Http\EndpointTable`: where each capture type's batch goes, which key the body wraps it under, which feature name attributes it, and which config key holds its timeout. `EndpointTable::contract()` is the four types `contract/endpoints.json` names, and `with()` lets a host append one of its own (the Laravel SDK adds its analytics `page_visits`, which is not part of the shared contract). The SDK name is deliberately NOT in the table: it is per SDK, not per endpoint, so `Endpoint::userAgent('PHP')` and `Endpoint::userAgent('Laravel')` build `Ranetrace-PHP/Errors/1.0` and `Ranetrace-Laravel/Errors/1.0` from one shared feature name
- `Http\ResponsePolicy`, `Http\BatchOutcome`, `Http\BatchCounters` and `Http\PauseScope`: the response matrix as data. One authority answers, per status, whether the batch goes back on the spool, what pauses and for how long, whether the items are terminal, and what the 200 counters and `unprocessed_indexes` mean. `Worker\Worker` consumes it, and so does the Laravel SDK's queued batch job. `BatchOutcome::$transient` is the seam between their two shapes: this package has no queue to release to, so a transient failure pauses on the spot and the next run is the retry, while the Laravel job spends its 60/300/900s envelope first. Both land on the same pause, which is the half the contract fixes
- `Errors\ErrorContext`: everything about the host an error item needs and a throwable does not carry. `fromServer()` derives it from a `$_SERVER`-shaped array, which is all a plain PHP host has; `provided()` takes each value as stated, which is what a framework adapter has. The values are RAW, so truncation, masking and redaction stay in one place and the two SDKs cannot bound the same field differently
- `Errors\PayloadBuilder` redacts the secret-bearing path segments of the reported URL and of the `Referer`, when the host can name them. A path segment carries no marker saying it holds a token and this package has no router to ask, so the values stay the caller's to supply: `ErrorContext::provided()` takes the current request's, plus a resolver for the `Referer`, which describes a request that is NOT the one being reported and so has to be matched separately. A host that cannot say keeps the previous query-only behaviour
- `Logging\LogItemBuilder`, `Events\EventItemBuilder` and `JavaScript\ErrorItemBuilder`: the three remaining item shapes, lifted out of the handler, the tracker and the relay so both SDKs compose the same keys, caps and markers. The event and JavaScript-error fingerprints are deliberately NOT computed there: each SDK salts its HMAC with what its own installs have always used, so centralising them would silently re-key every existing install's hashes and break the join between its events and its visits. They arrive already hashed
- `Support\Scrubber` and `Support\Diagnostics`, the two collaborator interfaces the shared builders take. They exist because a framework adapter has its own: the Laravel SDK resolves a URL's secret-bearing segments from its ROUTER, per URL, which a framework-agnostic scrubber cannot do, and it writes diagnostics to a dedicated log channel rather than to a file under the buffer directory. `SecretScrubber` and `InternalLogger` implement them, so nothing changes for this package
- `JavaScript\CaptureScript::withConfig()`, the seam that makes this package the one home of the browser capture script. It returns the bare script body with a caller-supplied runtime config substituted into it, and deliberately no `<script>` tag: the tag's attributes are the host's business, since this SDK takes a nonce as an option while the Laravel SDK asks `Vite::cspNonce()` for one. `ranetrace/ranetrace-laravel` carried a byte-identical copy of the same ~370 lines inline in `error-tracker.blade.php`, and because each SDK's relay validates exactly what its own copy sent, a fix applied to one silently stranded the other: nothing failed until a browser posted a shape the other relay did not accept. Both SDKs now render `resources/js/error-tracker.js`, each supplying its own config
- The capture script can send an `X-CSRF-TOKEN` header, when and only when the host puts a `csrfToken` in the config. The Laravel SDK's relay sits behind CSRF middleware and needs it; this SDK's relay verifies `Origin`/`Referer` instead and supplies no token, so nothing about what this SDK's script sends has changed. A capability only one host has now lives behind config rather than in a forked script, which is the rule for anything the two hosts do differently. A blank token counts as no token: it means no session was started, and an empty header would fail the check anyway
- Every captured item is held to a per-item byte budget on its way to the buffer: 70 KB JSON-encoded per item, 8 KB per field. Ported from `ranetrace/ranetrace-laravel` (`BaseRanetraceJob::capItemBytes()`) and already recorded as `client_item_policy` in `contract/envelope.json`, which the contract suite now asserts the constants against. An item within the budget is untouched. Over it, every string field above the per-field budget is cut and suffixed `... (truncated)`, and every array field above it is replaced wholesale, because truncating a structure mid-way yields invalid JSON. The capture paths already cap their own fields, but they cap characters where the API weighs bytes, and they cap fields one at a time where the budget is per item: twenty breadcrumbs of 5 KB each is 100 KB with no single cap exceeded. Without the budget one such item sits in the buffer until the worker sends it, and because the batch trimmer always keeps at least one item (a single item cannot be split) it draws a 413 that discards the whole batch and pauses the feature for fifteen minutes
- An item still over budget after shrinking is dropped outright and the loss is written to the internal log, under a message distinct from the shrink one. It is deliberately NOT replaced with a marker payload: the wire shape is an allow-list per type, so a top-level marker key belongs to no type, and on the errors endpoint strict field matching would reject the item and take the whole batch of up to a thousand items with it, which is the exact failure the budget exists to prevent. Losing one item is cheaper. The nested `_truncated` marker inside a free-shape field (log `context` and `extra`, JavaScript-error `context`, breadcrumb `data`) is a different thing and is unchanged
- The policy lives in one class, `Support\ItemByteBudget`, applied at each of the four buffer handoffs (errors, events, logs, JavaScript relay). This SDK has no base job to hook the way the Laravel SDK does, and the buffer implementations stay generic on purpose, so the four call sites share the class rather than each repeating the policy or it being buried in `FileBuffer`. It runs after scrubbing, so cutting a string cannot expose a secret past a redaction

### Changed
- **`Errors\PayloadBuilder::build()` takes an `ErrorContext` where it took `array $server, bool $isConsole`.** `ErrorContext::fromServer($server, $isConsole)` is the same thing for a plain PHP host, and `ErrorReporter` passes it, so nothing about what this SDK captures has changed. The class is internal to the capture path and no documented wiring calls it directly
- `Worker\Worker`'s private endpoint table and its `PAUSE_SECONDS` / `RATE_LIMIT_FLOOR_SECONDS` constants moved to `Http\EndpointTable` and `Http\ResponsePolicy`. The worker's behaviour, its diagnostics wording and its pause lengths are unchanged; the contract suite now asserts the shared classes against `contract/endpoints.json`, `contract/headers.json` and `contract/responses.json` row by row, where before it read the worker's constants through reflection
- `SecretScrubber` and the shared builders type-hint `Support\Scrubber` and `Support\Diagnostics` rather than the concrete classes. `SecretScrubber implements Scrubber` and `InternalLogger implements Diagnostics`, so every existing call site keeps working
- `JavaScript\Snippet` no longer reads or substitutes the script template itself. It builds the runtime config from `Config` and hands it to `CaptureScript`; the rendered `<script>` tag is unchanged apart from the endpoint URL keeping its slashes unescaped, which is safe because `JSON_HEX_TAG` escapes the `<` of a `</script>` on its own and never relied on the slash

### Security
- URL values inside breadcrumbs, log context and event properties are now recognised by their **shape** rather than by an `http(s)://` prefix. Previously a relative URL passed through untouched, so a signed download link recorded as `/exports/42/download?expires=…&signature=…` shipped its signature while the identical absolute URL was redacted. The shape test is deliberately strict — no whitespace, none of the characters that only turn up in prose, JSON and code, and a query that is a run of `key=value` pairs — because the redaction rewrites the query, and the fragment when that is query-shaped too, and a looser test would truncate a JSON log-context payload mid-structure. A value that fails the test is left byte-for-byte alone
- `SecretScrubber::scrubDeep()` takes the host's declared sensitive path segments and redacts them inside URL-shaped values, so a reset link the tracker recorded as a navigation breadcrumb loses its `{token}` the same way the top-level `url` field already did. Without it the same payload redacted the secret in one field and shipped it in another. A path segment carries no marker saying it holds a token and this SDK has no router to ask, so the values stay the caller's to supply: `Relay` and `EventTracker` pass whatever was given to their `setSensitivePathValues()`, and passing nothing keeps the previous query-only behaviour. The Monolog handler has no such channel, so log context is still query-only
- The JavaScript error `message` is scrubbed the way the sibling `stack` field already was. The bundled snippet's `unhandledrejection` handler `JSON.stringify`s the rejection value into `message`, so a rejected API response carrying an `api_key` reached the backend in full while the same text inside `stack` was redacted
- The JavaScript error relay's `timestamp` and `breadcrumbs.*.timestamp` fields are capped at 64 characters. They had no length rule and nothing downstream bounded them, so an unauthenticated client could buffer an item limited only by `post_max_size` — large enough to draw a 413 that discards the whole batch and pauses JavaScript error capture

- `SecretScrubber::scrubString()` now fails closed. Its pattern backtracks super-linearly on a long run of word characters, so PCRE can hit its backtrack limit and give up; the method then returned the input, shipping the exact string it had been asked to redact. It now returns `[REDACTED]` for the whole value and writes `preg_last_error_msg()` to the internal log, so a scrubber that has started swallowing strings is visible rather than silent. Losing the string beats leaking it
- The URL fragment is scrubbed. `scrubUrl()` copied it through untouched and `scrubUrlPath()` stopped at the first `?` or `#`, so both shapes of fragment secret survived: the query-shaped `/callback#access_token=…&expires_in=…` an OAuth implicit-flow redirect comes back as, and the path-shaped SPA hash route `/app#/reset/{token}`. A fragment that is query-shaped, judged by the same strict `key=value` run the relative-URL shape test uses, now goes through query scrubbing, and any fragment goes through path-segment scrubbing, which only replaces a segment that exactly equals a declared sensitive value. A fragment of any other shape, an anchor such as `#section-2`, comes back byte-for-byte
- `scrubUrlPath()` recognises a URL's scheme only at the start of the string. It searched for `://` anywhere, so a relative URL carrying an unencoded absolute one in its query or fragment (`/reset-password/{token}?next=https://app.test/dashboard`) put the path window inside the query, inspected the wrong substring as the path, and shipped the live token. The anchored match also covers the protocol-relative `//host/path` form, which used to be read as a path and is now read as an authority

### Known issues
- `SecretScrubber::scrubString()` still backtracks super-linearly on a long word-character run containing many sensitive fragments. The PCRE limit failure that follows is now a redaction rather than a leak, but the work is still done. Shared with `ranetrace/ranetrace-laravel` and unfixed in either
